## 接口注意事项（2026-08 核实）

- **新浪**：必须 HTTPS + `Referer: https://finance.sina.com.cn`（否则 403）；响应 **GBK**；前缀 A股 `sh/sz`、港股 `rt_hk`、美股 `gb_`+小写、场内 ETF 用 `sh/sz`（`sh518880` 已确认）；返回 `var xxx="a,b,c"` 文本，自写解析。腾讯 `qt.gtimg.cn` 作备用（间隔 ≥100ms）。
- **CoinGecko**：免费访问现需注册**免费 Demo Key**（100 次/分、1 万次/月）。
- **新股日历**：东方财富 `datacenter` 已限速，参考 **AKShare** 的 URL 构造照搬；数据以交易所为准。

## 房产（已确认方案 A：手动估值 + 70 城指数，v1 无抓取/无服务器）

**现实情况**：链家 / 贝壳 / 安居客**没有免费开放 API**，只能拿小区级挂牌均价，且有较强反爬（Cookie/滑块验证码）、HTML 易变、抓取违反其服务条款。综合成本与风险，**v1 不做中介抓取**。

**采用方案（已确认 · 完全本地）**：
1. **手动估值**：用户填「当前估值」，可随时手动更新（房价变化慢，够用）。
2. **指数辅助（可选开启）**：按**国家统计局 70 城房价指数**（官方公开、城市级、月度）对基准价做环比自动微调，趋势可靠。
3. **完全本地零成本、零运维、零合规风险**，符合「本地数据库」定位。
4. **预留升级位**：数据模型已含 `manualValue / autoUpdate / 指数回退`；**后续如需**自动抓小区均价，补一个 Cloudflare Workers 轻量代理即可，**不影响现有设计**。

## 省流量策略（核心）

1. **只查持有的标的**：只请求用户实际持仓的代码，不拉全市场。
2. **批量合并请求**：新浪/腾讯支持 `list=code1,code2,...` 一次拿多只，A股+港股+美股+ETF 合并成 **1 次请求**。
3. **每日 1 次定时抓取**：用 Android `WorkManager` 在**收盘后/次日早上**跑一次，**不做实时轮询**。
4. **加密货币 1 次批量**：CoinGecko 一次请求返回所有持有币种 × 三种法币价格。
5. **汇率 1 次/天**：只取 USD/CNY、HKD/CNY 两个汇率对。
6. **本地缓存 + 增量写库**：只把变化写入本地 SQLite；断网时用上次缓存值展示。
7. **开启 gzip、只取必要字段、不加载任何图片**。

**流量估算（典型用户，单日）**：股票批量 1 次（数 KB）+ 加密 1 次（~1 KB）+ 汇率 1 次（<1 KB）+ 金价（可选，<1 KB）
≈ **每天 < 20 KB**。一个月约 0.5 MB，几乎可忽略。

## 提醒的「重大」如何定义（需你确认阈值）

- **持仓相关提醒（本地即可，几乎零额外流量）**：
  - 存款：到期日倒计时（提前 7 / 30 天提醒，可配置）；
  - 持仓个股：公司公告（交易所披露：分红、停牌、业绩预告、重组、评级调整）+ 财经快讯中提及持仓标的的关键词；
  - 持有代币：大幅波动阈值（单日 ±5% / ±10% 可配置）+ 交易所 / 项目公告（上所、下架、硬分叉、网络升级）；
  - 持有 ETF / 公司股权 / 房产：分红、折溢价、房价指数更新等。
- **市场重大变化（规则化，免费可做）**：主要指数单日涨跌幅 ≥ **±3%**（沪深300 / 恒生 / 标普500，阈值可配置）；
  持仓个股单日 ≥ **±7%（A股）/ ±10%**；汇率单日 ≥ **±1%**。命中即推送。
- **重大国际事件 / 重大事项**：真正判断「重大程度」需新闻源。免费可行做法：
  - **财经日历**（重要经济数据/事件预告：非农、CPI、利率决议等，金十/东方财富有可用数据）；
  - **财经快讯关键词过滤**（加息/降息/关税/战争/央行/GDP/CPI 等关键词 + 影响权重打分）；
  - 你持仓相关的**公司公告**（分红、停牌、重组）。
  - v1 先用「财经日历 + 指数阈值 + 关键词打分」组合，避免依赖付费新闻 API。

## 架构（v1 完全本地，无服务器）

- **所有行情接口（股票/黄金/国债/加密/汇率）+ 70 城指数 → 纯客户端直连**，内置容错与重试；断网用本地缓存展示。
- **房产 → 手动估值 + 指数**，不抓取、无后端。
- **v1 没有任何服务器组件**，完全符合「本地数据库」定位。
- （后续可选）如加房产自动抓价，再单独引入一个 Cloudflare Workers 轻量代理，仅此一处用到后端。
